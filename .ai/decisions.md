# Decisions
- Part 2.2 (hybrid visual sources): real-world scenes (person/animal/landscape/object/place/room) default to LICENSED stock (Pexels photo -> Pixabay photo -> AI) because real photography avoids AI anatomy defects (2 faces/4 hands) and no AI repair model is used; abstract/cartoon/fictional/surreal stay AI-first with stock re-fallback. `VISUAL_SOURCE_MODE` (auto|stock|ai|local) is a global override; per-scene `visual_source_preference` wins in AUTO. Each source is tried AT MOST ONCE per scene (finite chain = no loops, no API fan-out). Local assets (projects/<id>/assets/**, assets/stock/**) are usable with zero API calls via `visual_source_preference: "local"` or mode `local`. Keys come ONLY from env (PEXELS_API_KEY/PIXABAY_API_KEY), are redacted from every error string, and Pexels uses the Authorization header (never URL). Pixabay search results and stock assets are cached in the existing CacheManager `stock` category keyed by provider+query+media+size+`STOCK_CACHE_VERSION` (respecting provider rate limits: HTTP 429 stops the provider immediately, no retry storm). Duplicate assets are penalized via `visual_meta_*` ids in state. Every downloaded asset gets provenance metadata (provider/asset_id/media_type/source_url/creator/query/license/downloaded_at/project_id/scene_id); API keys never stored. Stock VIDEO is opt-in per scene (`stock_media: "video"`, gated by `STOCK_ALLOW_VIDEO`) and renders through the same chunk renderer family. Captions remain renderer-side; AI image prompts remain visual-only; review + manual YouTube publishing unchanged. No Google Images scraping, no Selenium/Playwright, no automatic upload.

- Part 4 P2: review is human-only; APPROVED is never automatic; history is append-only.
- Part 4 P3: OAuth tokens stored ONLY in YOUTUBE_TOKEN_FILE (git-ignored, outside projects/); state.json holds safe youtube metadata only (status/video_id/url/privacy/title/uploaded_at) — never tokens/secrets; upload gate = final video + review APPROVED (via is_approved_for_publishing) + OAuth connected + not already uploaded, enforced in service layer AND uploader; default privacy private; duplicate upload → 409; errors redacted; tests use TEST_YOUTUBE_MODE mock client, never real uploads.
- Part 4 P1: dashboard is strictly read-only (no generation/AI calls on dashboard routes); new `app/dashboard/` package alongside existing code; no auth yet (deliberate, later prompt); polling instead of SSE/WebSocket since none existed; logs parsed from existing logger file output instead of adding a second logging system; project-id validation regex blocks path traversal.
- Part 4 P2: review state lives INSIDE existing state.json via existing StateManager (atomic) — no separate review store. NOT_READY/PENDING are DERIVED (not persisted) so old projects never get rewritten; only real actions persist `review`. Approve requires a valid final video; reject requires a note; reset only from APPROVED/REJECTED; history is append-only. GET video route serves only output/final_video.mp4 via ProjectManager paths. Reviewer is a constant `local_user` — explicitly NOT authentication. `is_approved_for_publishing()` is the future upload gate; nothing uploads. Frontend escaping fixed with esc() during this prompt.
- Part 2 FIX (visual/caption separation): image prompts are visual-only (`visual_prompt`/`visual_direction` sanitized; narration/caption never sent to image gen). Global `VISUAL_NEGATIVE_PROMPT` (no text/typography/...) wired into ComfyUI node 7 and image cache key. Captions render ONLY in scene renderer (`app/video/caption_overlay.py` + `chunk_renderer.render_scene_chunk(..., caption_text)` -> `*_framed.png` -> Ken Burns). Image cache bumped to `VISUAL_CACHE_VERSION=v2_no_text` so v1 text-embedded images never reuse. Test provider emits clean gradient scene (scene-id tag only). Script schema extended backward-compatibly (`narration_text`/`visual_prompt`/`caption_text` + `normalize_scene()`); LLM prompt now forbids `Text: ...` in `visual_direction`. No architecture duplication; review/YouTube flows untouched.
- Part 2.1 (robust script generation): small-model JSON defects are repaired STRUCTURALLY, not by re-asking the LLM for the parts it already produced. `parse_script_json()` = whole-text first, then `_close_containers()` (closes only the missing final `]`/`}` that llama3.2:3b habitually omits), then it DROPS a trailing half-written scene (never invents narration/visual). Missing duration stays derived from narration (existing `estimate_duration`, clamped to `SCENE_MIN_SECONDS`/`SCENE_MAX_SECONDS`); empty/whitespace narration stays FATAL and goes through the existing 3-attempt retry, whose correction is now compact + actionable (JSON syntax vs schema) instead of possibly empty. Duration/empty-narration fallbacks remain in `pre_validate_script` (pre-Pydantic), so they never burn retries. `--resume` retries SCRIPT when it is in `failed_steps` (`script_is_resumable`) instead of dead-ending. Script model context raised via `SCRIPT_NUM_CTX`/`SCRIPT_MAX_TOKENS` config (no new config system). No second script engine, no duplicate validators, and Part 2 separation untouched.
